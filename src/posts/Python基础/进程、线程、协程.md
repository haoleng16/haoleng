# 进程、线程、协程

>进程、线程、协程，本质上都是为了让程序同时处理多个任务，但它们的调度层级、资源隔离程度和使用成本不同。

## 进程
**进程是操作系统进行资源分配和隔离的基本单位**

一个程序运行起来之后，通常就会对应一个或多个进程。每个进程都有自己独立的
- 内存空间
- 全局变量
- 文件描述符表
- 堆和栈
- 代码段和数据段

例如启动两个Python程序，它们通常运行在两个独立进程当中，一个进程崩溃，一般不会直接破坏另一个进程的数据。

进程之间内存不共享，如果需要通信，通常需要使用
- 管道
- 消息队列
- Socket
- 共享内存
- Redis、Kafka等外部中间件

进程的优点是隔离性强、稳定性强，并且可以真正利用多核CPU；缺点是创建、销毁和上下文切换成本高。

## 线程
**线程是操作系统进行CPU调度的基本单位，也是进程内部的执行单元**

一个进程可以包含多个线程。线程之间共享进程的：
- 堆内存
- 全局变量
- 文件资源
- 网络链接

但每个线程拥有自己独立的：
- 调用栈
- 程序计数器
- 寄存器
- 局部变量

例如一个web服务进程可以创建多个线程，同时处理多个客户端请求。

线程之间因为共享内存，所以通信方便，但也容易产生并发生安全问题。例如：

```python
count += 1
```

多个线程同时修改count，可能导致数据不一致，所以通常需要使用：
- 互斥锁
- 读写锁
- 信号量
- 条件变量
- 原子操作

## 协程
协程是运行在线程之上的用户态轻量级任务。

协程不是由操作系统直接调度，而是由程序中的事件循环或协程运行时进行调度。在 Python 中，例如：

```python
async def get_data():
    await asyncio.sleep(1)
```

`get_data()` 就是一个协程函数。当协程执行到：

```python
await
```

如果当前操作需要等待（例如等待网络响应），它会暂停当前协程，把执行权交给事件循环，让事件循环去执行其他协程；等待完成后，再恢复当前协程。

协程的暂停和恢复通常发生在用户态，不需要频繁进入操作系统内核，因此创建成本和切换成本都非常低。一个线程中可以运行成千上万个协程。

但是协程一般不能自动利用多个 CPU 核心。多个协程通常还是运行在同一个线程中，如果某个协程执行了长时间的同步计算，就会阻塞整个事件循环。

## 三者之间的区别

| 对比项  | 进程      | 线程       | 协程        |
| ---- | ------- | -------- | --------- |
| 调度者  | 操作系统    | 操作系统     | 用户程序、事件循环 |
| 资源关系 | 内存相互独立  | 共享进程资源   | 共享所属线程资源  |
| 创建成本 | 最高      | 中等       | 最低        |
| 切换成本 | 最高      | 中等       | 最低        |
| 通信方式 | IPC，较复杂 | 共享内存，较方便 | 直接共享变量    |
| 隔离性  | 最强      | 较弱       | 最弱        |
| 并发数量 | 通常较少    | 几十到几百    | 可以成千上万    |

**总结：**
进程是操作系统资源分配的最小单元，而线程是操作系统 CPU 执行调度的最小单元。协程是线程内部的用户轻量级的执行单元，通常用作等待——让线程去执行其他协程，等线程执行完其他协程的时候再来执行。

进程默认隔离内存，如果需要通信需要通过管道、消息队列、Redis 和 Kafka 进行通信；而线程是进程的内部单元，直接共享进程内存。

>一句话记忆：
>**进程管资源，线程管执行，协程管等待**
